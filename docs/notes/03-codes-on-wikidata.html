Field note 3 · covers October – November 2026

Development codes on Wikidata

The second question from the first field note: can an open data community hold development codes?

Why

On Wikidata, development codes were aliases. An alias has no reference, no company, and no way to say it is wrong without deleting it. Some aliases repeated errors of the sources they came from. On abatacept, the aliases RG-2077 and CTLA4-IgG4m name a different construct, an IgG4 fusion protein in two NIAID trials. On ocrelizumab, the alias PR-070769 is a typo of the Genentech code PRO70769; NCI Thesaurus has the same typo.

None of the existing properties fitted. So I proposed a new one, and in October 2026 the community created P15001 "development code" (proposal). A code is now a statement, with the company that assigned it ("conferred by") and a reference.

What was done

The rules are conservative: nothing is published that depends on an assumption.

  • Which codes. Only codes I confirmed in review, accepted by the evidence rule and used in search.
  • Which item. The item of the level the code names: active moiety, salt (only where the evidence names the salt) or fixed combination. Items are found by UNII.
  • Which reference. A ClinicalTrials.gov record with the assigning company as lead sponsor; otherwise NCI Thesaurus if it is a source; otherwise not published. PubChem and Wikipedia are not used as references.

What I learned

  1. A code names a level. Active moiety (AZD7986), salt (DS-6051b, of which DS-6051a is the free base), combination (LNZ101: aceclidine + brimonidine), or a development programme (Novo Nordisk's NN9535). Wikidata has items for the first three. ISO IDMP has no structural place for development codes, and no programme level.
  2. A company is another case of what to identify. "Conferred by" needs the company that assigned the code as one thing, across subsidiaries, joint ventures, mergers and renames, and company items do not always carry the names the registry uses. The same question as for the drug: what exactly is it we identify? Details: Identity findings.
  3. Most holds are about identity, not about the code. In 27 of the 31 holds the code is confirmed; what is open is which item, which company, which level, or which spelling.
  4. Linked Data shows these details early. Each of them had to be decided before a statement could be made. Other approaches leave them to be handled in software later, or never.

Why it matters

For Value
Open data P15001 makes a code verifiable (reference), attributable (conferred by) and correctable. An alias is none of these.
Master data and ISO IDMP Development codes behave as identifiers with an assigner, a time span and a level. That is evidence for giving them a place in the model, and for a level above Product Family (the "Product Clan") that covers the whole R&D lifecycle.
Method An LLM writes the code and helps find sources; the pipeline itself is deterministic, every decision is in a file, and a person confirms what is published.

Open questions

  • Who is "the company" across subsidiaries, joint ventures and acquisitions, and where should that be resolved: in Wikidata, in the registry, or in each sponsor's master data?
  • Should registries record the development code as a typed identifier of the intervention, with its assigner?
  • How should a development programme (one moiety, one formulation, one indication) be represented, when neither Wikidata nor IDMP has the level?
