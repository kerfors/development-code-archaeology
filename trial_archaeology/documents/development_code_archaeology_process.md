# Development Code Trial Archaeology

## Process overview

How the repository finds clinical trials that an INN-only search misses: harvest candidate development
codes from named sources, review them against registry evidence, then search AACT with the INN and the
accepted codes under one matching rule.

Earlier rounds (December 2025: AI-assisted discovery; February 2026: PubChem structure checks) are
described in `docs/background.md`.

---

## The problem

A drug accumulates identifiers during development:

```
AZD0914 (AstraZeneca) → ETX0914 (Entasis) → zoliflodacin (INN)
```

Trials registered early use only the sponsor's code. A search for "zoliflodacin" misses trials registered
as "AZD0914" before the INN was assigned.

---

## Workflow

```
Sources                         Harvest                   Review                  Search
─────────────────────────       ──────────────────        ───────────────         ──────────────────
NCI Thesaurus synonyms   ─┐
PubChem synonyms          ├──►  candidates          ──►  evidence rule     ──►   trial archaeology
AACT other names          │     (INN × code key)          + human review          INN + accepted codes
AACT interventions.name   │     + AACT evidence           + exceptions            shared matching rule
Web (URL-cited)          ─┘                                + expert questions
```

- Harvest: `code_harvest/notebooks/development_code_harvest.ipynb` (generated by
  `code_harvest/tools/build_harvest_notebook.py`). Sources and their known weaknesses are in the
  notebook's sources table.
- Evidence rule: a code with two or more independent lines of evidence (sources, web publishers,
  registry trials) is accepted; NCIt-labelled biosimilars are excluded. Checkable without domain expertise.
- Review: each candidate gets a class (current, legacy, partner, other_product, biosimilar, other_drug,
  typo, not_a_code) in `collections/<collection>_code_review.csv`. AI-proposed classes are marked
  `claude-proposed` until a person confirms them. Where review and rule disagree, the row goes to
  `<collection>_review_exceptions.csv` for independent verification and, if still open, an expert question.
- Search: `trial_archaeology/notebooks/development_code_trial_archaeology.ipynb` (generated by
  `trial_archaeology/tools/build_archaeology_notebook.py`).

The two collections enter at different points:

| Collection | Codes from | Harvest and review |
|------------|-----------|--------------------|
| `fda_novel_2025` | December 2025 discovery and verification | No; codes go straight to the search |
| `top_sellers_fy2025` | October 2026 harvest | Yes |

## Shared matching rule

`patterns/aact_matching.py`, pasted into both notebooks by their builders:

- Code as a token: no letter or digit directly before or after, in all spellings (as given, no separator,
  space/hyphen swapped, prefix/number split). MK-3475 finds MK-3475-001 but not MK-3475A.
- INN: the full INN in `interventions.name`.
- Study-code patterns, `patterns/study_code_patterns.csv`, under the admission rule in `patterns/README.md`.
- Code-scoped exclusions for token collisions the rule cannot see (XM02-ONC-201 for ONC201).
- Worked cases as asserts; a new review finding becomes a new assert.
- Residue report: `id_information` values that contain a code key but match neither the token search
  nor a pattern, for human review.

### AACT fields searched for codes

| Table | Field | Content |
|-------|-------|---------|
| `interventions` | `name` | Intervention name |
| `intervention_other_names` | `name` | Aliases, synonyms, development codes |
| `studies` | `official_title`, `brief_title` | Trial titles |
| `id_information` | `id_value` | Sponsor study codes and secondary IDs |

### Study-code patterns

| ID | Sponsor observed | Description | Example |
|----|------------------|-------------|---------|
| P1 | Novartis | C + code + letter, study part follows | CLCZ696B1401 |
| P2 | Janssen | Code + 3-5 letters + 4 digits | CNTO1959PAP4001 |

Study codes that do not contain the development code (e.g. AstraZeneca D-codes) are not searched.

## Lessons (October 2026)

1. **NCIt merges biosimilar codes into the originator concept**, labelled "X Biosimilar CODE", so they
   can be filtered.
2. **AACT is not independent of NCIt for oncology.** NCI-sponsored records appear to carry NCIt synonym
   lists as other names (inferred from the sponsor pattern, not confirmed), including biosimilar codes
   (73 of 81 trials with nivolumab "ABP 206" are NCI-sponsored).
3. **Some current codes exist only in the registry**: tirzepatide LY3298176 and emicizumab RO5534262 are
   in neither NCIt nor PubChem.
4. **Other names include other products and other drugs**: co-formulations (MK-7684A), fixed-dose
   combinations (BMS-986213) and combination partners (AZD2281 under dapagliflozin). Unreviewed, these
   inflate the hidden count.
5. **PubChem depositor synonyms contain typos**: GSK685968 next to GSK685698, LY2385219 next to LY2835219.
6. **Brands are not a search unit for big sellers.** Shared moieties (semaglutide in three brands) and
   combinations (valsartan in Entresto and Diovan) make the active moiety the unit of trial search.
7. **One matching rule for harvest and search.** The two notebooks had drifted to different rules
   (fields, boundaries, INN term); both now use `patterns/aact_matching.py`.
