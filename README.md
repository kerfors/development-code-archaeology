# development-code-archaeology

Development codes (AZD0914, BI 1015550, MK-3475) are how a drug is named in clinical trials before it has an
INN, and often after. A ClinicalTrials.gov search on the INN alone misses the trials registered under a code.
This repository harvests and reviews development codes, counts the trials they recover, and publishes the
reviewed codes to Wikidata.

It follows up a holiday project from December 2025, published as two LinkedIn articles (30 December 2025):

- [Data Archaeology: Tracing Drug Development Codes Through Name Changes, Mergers, and Licensing Deals](https://www.linkedin.com/pulse/data-archaeology-tracing-drug-development-codes-through-forsberg-89t1e/)
- [Searching AACT for Development Codes: A Practical Guide](https://www.linkedin.com/pulse/searching-aact-development-codes-practical-guide-kerstin-forsberg-2rhze/)

That work found a third of the trials of the 2025 FDA novel small-molecule approvals reachable only by a code,
and ended with open questions. Two of them are worked on here: can codes be harvested programmatically from
named sources, and can an open data community hold them?
See `docs/background.md`.

## Repository structure

| Folder | Content |
|--------|---------|
| `collections/` | Drug collections as data files, plus review and evidence files for harvested codes |
| `code_harvest/` | Harvests candidate codes from named sources and collects registry evidence |
| `patterns/` | Shared AACT matching rule and sponsor study-code patterns |
| `trial_archaeology/` | Searches AACT with INN and codes; counts trials found only via codes |
| `wikidata/` | Publication of reviewed codes with property P15001 "development code" |
| `docs/` | Background: December 2025 and February 2026 |

Notebooks are generated by the builder scripts in `<folder>/tools/`; edit the builder, not the notebook.
Run outputs go to `<folder>/output/`, which is not tracked.

## Workflow

1. **Harvest** candidate codes from named sources: NCI Thesaurus, PubChem synonyms, AACT intervention other
   names and intervention names, plus LLM-assisted web discovery in which every code must cite the page where
   it was seen (`collections/<collection>_web_candidates.csv`). No code enters without a source.
2. **Evidence**: per candidate, the trials in AACT where the code appears, and their lead sponsors.
3. **Rule**: a code with two or more independent lines of evidence (sources, web publishers, registry trials)
   is accepted; NCIt-labelled biosimilars are excluded. Checkable without domain expertise.
4. **Review**: each candidate gets a class (current, legacy, partner, other product, biosimilar, other drug,
   typo, not a code). AI-proposed classes are marked `claude-proposed`. Where review and rule disagree, the row
   goes to an exception list for independent verification and, if still open, an expert question.
5. **Search**: trial archaeology with INN plus accepted codes.
6. **Publish**: reviewed codes as referenced Wikidata statements (`wikidata/README.md`).

## Requirements

- Python 3.10+, pandas, requests, psycopg2, openpyxl
- Free AACT account: https://aact.ctti-clinicaltrials.org/users/sign_up. Credentials go in `.env` at the repo
  root (git-ignored; keys as in `.env.example`).

## Status

Exploratory. Results depend on the AACT snapshot and on the source versions at harvest time; each run records
its dates. `top_sellers_fy2025`: 2 codes held for an expert question. `fda_novel_2025`: codes harvested and
reviewed 2026-11-07 (54 confirmed, 7 held); its trial counts above still use the December codes.
Wikidata: 41 P15001 statements published from both collections (25 + 16, 2026-11-07; `wikidata/README.md`).
